You are extending the Three.js scrollytelling system already implemented for the Dev and 
Marketing portfolios (motherboard scene / marketing scene with camera-driven scroll narrative).

## Goal
Add a complete 2D fallback experience that fully replaces the 3D scene on devices/conditions 
where WebGL performance would degrade the experience, while preserving the same narrative 
structure (camera "arriving" at each section, content revealing progressively) using only 
Framer Motion and CSS — no WebGL at all.

## When the fallback activates
- `useDeviceCapability` (already built) returns "incapable" or "lite-and-still-struggling" — 
  define a clear, conservative threshold (low `hardwareConcurrency`, small screen + no GPU 
  acceleration signs, or a runtime FPS check during the first few seconds of the 3D scene that 
  triggers a switch if frame rate drops below ~30fps sustained)
- WebGL is unavailable or fails to initialize (catch context creation errors)
- User has `prefers-reduced-motion` set AND lite mode would still be too heavy (reduced-motion 
  alone should keep a static lite 3D scene per the previous implementation — this fallback is a 
  separate, more aggressive tier for genuinely low-power devices)
- Optional: manual toggle in a settings/accessibility menu so users can opt into the lighter 
  experience regardless of detected capability

## Fallback design concept
Recreate the SAME narrative beats as each 3D scene, translated into 2D layered illustrations 
with Framer Motion parallax and reveal animations:

### Dev portfolio fallback
- Replace the motherboard scene with a flat/SVG-illustrated circuit board background (a single 
  well-designed SVG asset, not generated geometry) using the same Sky Blue/Violet glow language
  via CSS box-shadow/filter:drop-shadow instead of WebGL bloom
- As the user scrolls, use Framer Motion's `useScroll` + `useTransform` to animate:
  - Opacity/glow of specific circuit paths or "chips" turning on per section (matching the same 
    Hero → About → Skills → Projects → Contact mapping)
  - Subtle parallax between 2-3 flat layers (background board, mid-layer traces, foreground glow 
    highlights) to simulate depth without 3D
- Content overlays normally on top (standard HTML/CSS layout) — no attempt to anchor text "inside" 
  the scene like the 3D version; simplicity is the point here

### Marketing portfolio fallback
- Same approach: flat SVG illustration matching whatever concept was chosen for the 3D Marketing 
  scene (e.g. if it's a growth/data concept, animate bars/lines drawing in via Framer Motion's 
  `pathLength` animation as each relevant section scrolls into view)
- Same 2-3 layer parallax treatment for a sense of depth

## Scroll behavior in fallback mode
- Drop the snap-scroll requirement — use normal smooth native scroll (snap-scroll was partly in 
  service of the camera choreography, which no longer applies)
- Section reveal animations trigger via `useInView` (Framer Motion) or scroll-linked `useTransform` 
  as the section enters the viewport — standard scroll-reveal pattern, not a forced narrative 
  sequence

## Technical requirements
- Build as `src/fallback/dev/DevFallbackScene.tsx` and `src/fallback/marketing/MarketingFallbackScene.tsx`
- These should consume the SAME section content components where possible (don't duplicate copy/
  translations — reuse the existing section content, just change how it's visually staged)
- SVG assets: create simple, clean vector illustrations inline as React components (not external 
  image files) so they can have currentColor/CSS variable theming consistent with the rest of 
  the site
- Wire detection logic into `PortfolioSwitcher.tsx` (or a new `Scene3DOrFallback.tsx` wrapper) 
  so the decision of which experience to render happens once on mount, with the FPS-based 
  fallback able to switch mid-session if needed (show a brief, non-intrusive notice like 
  "Switched to lite mode for better performance" if this happens automatically)
- Ensure NO Three.js/R3F code is even loaded (dynamic import) when the fallback path is chosen — 
  this fallback must keep bundle size and runtime cost minimal, that's its entire purpose

## Testing checklist
- [ ] Fallback renders correctly with zero WebGL/Three.js code loaded (verify via network tab — 
  no R3F chunk requested)
- [ ] Section reveal animations are smooth on a throttled CPU (use Chrome DevTools CPU throttling 
  4x-6x to simulate low-end mobile)
- [ ] Automatic mid-session fallback (FPS-based) triggers correctly and transitions gracefully 
  without a jarring layout jump
- [ ] Visual identity (colors, glow language, section pacing) feels like a clear "lighter sibling" 
  of the 3D version, not a completely different design
- [ ] All copy/translations (PT/EN/ES) render identically to the 3D version since content is reused
